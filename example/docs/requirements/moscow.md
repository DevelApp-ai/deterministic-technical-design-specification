# MoSCoW Requirements — Deterministic Documentation Example

This document codifies the business and technical requirements for the
example deterministic documentation pipeline using the MoSCoW prioritisation
method.  It is maintained as code alongside the source repository so that
CI/CD pipelines can generate traceability matrices linking each requirement
to the specific Terraform module, Ansible role, or OPA policy that satisfies it.

---

## Must Have

These requirements are non-negotiable.  The system cannot be considered
functional without them.

| ID | Requirement | Satisfied By |
|----|-------------|-------------|
| M-001 | Infrastructure must be defined as code (Terraform HCL) | `terraform/main.tf` |
| M-002 | Every resource must carry the four mandatory FinOps cost-allocation tags (`environment`, `app_name`, `owner`, `cost_center`) | `policies/terraform/deny_missing_tags.rego` |
| M-003 | OPA policy violations must block the CI/CD pipeline before `terraform apply` | `.github/workflows/docs-pipeline.yml` — OPA gate step |
| M-004 | Terraform documentation must be auto-generated by `terraform-docs`; no hand-written input/output tables are permitted | `scripts/generate-docs.sh` |
| M-005 | All significant architectural decisions must be recorded as ADRs in `docs/adrs/` | `docs/adrs/0001-*.md`, `docs/adrs/0002-*.md`, `docs/adrs/0003-*.md` |
| M-006 | The complete documentation site must be buildable from a single Docker image with no host dependencies | `Dockerfile` |

## Should Have

Important requirements that add significant value but have a known workaround
if omitted from the current iteration.

| ID | Requirement | Satisfied By |
|----|-------------|-------------|
| S-001 | OPA policies must include self-describing `__rego__metadoc__` blocks so compliance reports are human-readable | `policies/terraform/*.rego` |
| S-002 | OPA policy unit tests must achieve 100 % rule coverage | `policies/terraform/*_test.rego` |
| S-003 | Ansible playbook must use `setup` module to gather live host facts and render them via Jinja2 templates | `ansible/playbook.yml`, `ansible/templates/host-report.md.j2` |
| S-004 | MkDocs site must include a searchable ADR index and a compliance chapter | `mkdocs.yml` nav section |
| S-005 | The CI/CD pipeline must publish the MkDocs site to GitHub Pages on every merge to `main` | `.github/workflows/docs-pipeline.yml` — deploy step |
| S-006 | Full traceability chain (OPA policy → ADR → MoSCoW requirement) must be machine-readable and rendered as diagrams | `__rego__metadoc__` `related_adr`/`related_requirements` fields; ADR front-matter; `docs/traceability/index.md` |
| S-007 | Backstage `catalog-info.yaml` must be present so the component is discoverable in any Backstage developer portal | `catalog-info.yaml`, `backstage/app-config.yaml`, `Dockerfile.backstage` |
| S-008 | PowerShell DSC resources must be implemented as class-based modules with comment-based help, and documentation auto-generated by `DscResource.DocGenerator` | `dsc/resources/DTDS_FileContent/`, `dsc/build.ps1`, `docs/generated/dsc-resources.md` |
| S-009 | DSC resource unit tests must validate Get/Test/Set idempotency contract using Pester 5 | `dsc/tests/DTDS_FileContent.Tests.ps1` |

## Should Have — Cybersecurity

| ID | Requirement | Satisfied By |
|----|-------------|-------------|
| CYB-001 | Architecture overview page with C4-style diagrams (C4Context, C4Container, C4Component) and technology radar | `docs/architecture/index.md` |
| CYB-002 | OPA policy must block publicly exposed resources (S3 public ACL, security group open to 0.0.0.0/0 on sensitive ports, Azure public blob) | `policies/terraform/deny_public_access.rego` |
| CYB-003 | OPA policy must block overly permissive IAM (wildcard principals, wildcard actions on sensitive services) | `policies/terraform/deny_public_iam.rego` |
| CYB-004 | OPA policy must block unrestricted network egress and non-RFC-1918 subnet CIDRs | `policies/terraform/deny_unrestricted_network.rego` |
| CYB-005 | Security controls matrix must map every OPA policy to CIS benchmark, NIST 800-53, and SOC 2 CC controls | `docs/security/index.md` |

## Won't Have (in this iteration)

These requirements are explicitly out of scope.  Documenting them here
protects against unauthorised scope creep.

| ID | Requirement | Rationale |
|----|-------------|-----------|
| W-001 | Real cloud resource provisioning (AWS, Azure, GCP) | This example uses the `local` provider to avoid credential management |
| W-002 | Multi-tenancy or RBAC for the developer portal | Single-team scope; revisit when Backstage is adopted (C-002) |
| W-003 | Runtime configuration management via Ansible against live hosts | Example uses static inventory; live targets require SSH access |
